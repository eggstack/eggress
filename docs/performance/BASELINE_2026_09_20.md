# Runtime performance qualification — 2026-09-20

This is a local qualification record for the Phase 1–3 performance campaign,
not a portable CI threshold or a replacement for the historical baseline.

## Environment

- Commit during qualification: working tree based on `d9abcff` (campaign plan)
- Rust: `rustc 1.85.0 (4d91de4e4 2025-02-17)`
- Target: `x86_64-unknown-linux-gnu`
- OS/kernel: Ubuntu Linux, `6.8.0-139-generic`, PREEMPT_DYNAMIC
- CPU: Intel Core i9-9900K, x86_64, 16 logical CPUs
- Profile: Criterion bench profile (`--release`), default workspace features
- Criterion smoke settings: sample size 10, 100 ms warmup, 100 ms measurement

## Qualification observations

Representative medians from the same host/run:

| Path | Observation |
|---|---:|
| Cached default verified TLS access | ~10 ns |
| Cached default H2 TLS access | ~9 ns |
| Chain executor construction | ~181 ns |
| Listener server-config construction | ~23.5 µs |
| Steady 64 KiB relay | ~200 µs per transfer |
| Steady 16 × 64 KiB relay | ~665 µs per batch |
| UDP 64 B existing-flow path | ~31 µs per datagram |
| UDP 8-target admission batch | ~264 µs per batch |
| Route selection | ~217 ns (1 member) to ~1.96 µs (128 members) |

Commands used:

```bash
cargo bench --bench tls_setup -- --sample-size 10 --measurement-time 1
cargo bench --bench route_match -- route_select --sample-size 10 --warm-up-time 0.1 --measurement-time 0.1
cargo bench --bench udp_relay -- udp_runtime --sample-size 10 --warm-up-time 0.1 --measurement-time 0.1
cargo bench --bench tcp_relay -- steady --sample-size 10 --warm-up-time 0.1 --measurement-time 0.1
```

The compatibility relay facade retains two 64 KiB buffers and its one-second
bounded drain. The evidence is sufficient to qualify the moved setup and hot
paths, but not to justify changing that compatibility tuning or introducing a
UDP buffer pool. Owned UDP buffers and HTTP forward connection reuse remain
unchanged/deferred.
