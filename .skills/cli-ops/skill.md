# CLI and Operations

## When to use
Use when modifying the native `eggress` CLI, the compat `pproxy` binary
surface, exit codes, structured diagnostics, the admin HTTP endpoints,
Prometheus metrics, or the system-proxy integration. For the pproxy URI/flag
translation internals, see also `.skills/rust-proxy-dev/skill.md`
(pproxy-style binary) and `architecture/pproxy-compat.md`.

## Binaries (`eggress-cli`)

One crate installs two binaries (`crates/eggress-cli/src/main.rs`,
`src/pproxy_main.rs`); both converge on the same `ServiceSupervisor` and
differ only in how arguments reach config.

### Native `eggress`

Top-level flags: `-l/--listen` (repeatable listener URIs),
`-r/--remote` (repeatable upstream URIs, `__` chains), `-c/--config`
(single global TOML source: valid before or after the subcommand),
`--rules-file`, `--log-format pretty|compact|json` (typed: typos exit 2).

Subcommands:

- `version` — print `eggress X.Y.Z` deterministically (no network/config) and
  exit 0. `eggress --version` remains functional.
- `update` — self-update the standalone pair from verified GitHub Release
  assets (flagless; checksum + staged-version verified, transactional
  two-binary replace, no sudo, no background checks; never touches `pip`
  environments). Installer re-runs remain a supported equivalent.
- `route <target> [--listener] [--protocol http|socks4|socks5] [--json] [--admin URL]` —
  explain the routing decision for a target (offline via config or live via
  the `eggress-admin` client against `/-/route-explain`).
- `upstream test [-i id] [-t HOST:PORT] [--timeout 5] [--mode proxy|tcp] [--json]` —
  test upstream reachability in `proxy` (production connector traversal) or
  `tcp` (first-hop check) mode, then exit. Requires the global `--config`.
  `--mode` is a typed enum (typos exit 2 at parse); the shared library
  rejects any other mode string with exit 2 instead of falling back.
- `pproxy translate -- <pproxy args> [--annotate]` — print generated TOML
  (`# Generated by eggress pproxy translate`); never starts a service.
- `pproxy check -- <pproxy args> [--json]` — print the compatibility report
  (`PproxyCheckOutput`); never starts a service.
- `pproxy run -- <pproxy args>` — translate and run through the shared
  fail-closed facade (`eggress-cli::pproxy_exec`, same pipeline as the
  standalone `pproxy` binary).
- `system-proxy inspect [--json]` (behind `operations`) — read-only
  inspection of OS proxy settings. Native inspection never mutates; only the
  compat `--sys` path applies settings (post-bind) with rollback.

`src/main.rs` is a thin parse/dispatch boundary; handlers live in
`src/commands/` (typed `CliContext`, no `process::exit` inside), the schema
in `src/cli.rs`, self-update in `src/update/`.

### Compat `pproxy`

Frozen 2.7.9 flag parser with a fail-closed execution gate: unknown,
unsupported, and non-equivalent options cannot start a partial service from
either the standalone binary or `eggress pproxy run`. `--daemon` is fatal
unless the `pproxy-daemon` feature is enabled (Linux safe re-exec).
`--version` prints `eggress-pproxy-compat {VERSION}`. The standalone binary
stays flat (no `pproxy translate/check/run` subcommands); nested migration
tooling lives only under native `eggress`.

Standalone install/update provenance lives in `docs/INSTALLATION.md`:
prebuilt GitHub Release archives contain `eggress`+`pproxy` at one version
(default features); installers and `eggress update` both verify SHA-256
plus both staged versions before replacing either binary.

## Exit codes

Single owner is `eggress-pproxy-compat::exit_codes` (typed `ProcessExit`
+ numeric constants; `eggress-cli` re-exports) — never ad-hoc
`process::exit` or raw numbers. Ten stable codes:

| Code | Constant | Meaning | Wired call sites |
|---|---|---|---|
| 0 | `EXIT_SUCCESS` | Clean run / check passed | everywhere |
| 1 | `EXIT_RUNTIME_FAILURE` | Runtime failure | supervisor/drain, daemon-spawn, update verify/replace |
| 2 | `EXIT_CLI_PARSE_ERROR` | CLI/flag parse error (incl. strict-gate rejection, bad closed-domain values) | Clap rejections, strict gate, invalid release tag |
| 3 | `EXIT_CONFIG_VALIDATION` | Config validation failure | TOML load/compile, empty upstream set |
| 4 | `EXIT_BIND_FAILURE` | Listener bind failure | native bind-before-spawn (fails closed, no partial serve); native `--config` startup and compat supervisor bind/admin-bind failures via `runtime_error_exit_code()` |
| 5 | `EXIT_UNSUPPORTED_FEATURE` | Unsupported feature / composition | compat gate blockers |
| 6 | `EXIT_PLATFORM_MISSING` | Required platform facility unavailable | `--daemon` off Linux, updater on unsupported target |
| 7 | `EXIT_EXTERNAL_DEPENDENCY` | External dependency unavailable | updater discovery/download/tool failures |
| 130 | `EXIT_SIGINT` | Terminated by SIGINT | Unix Ctrl-C / Windows Ctrl-C |
| 143 | `EXIT_SIGTERM` | Terminated by SIGTERM | Unix SIGTERM |

Tests: `cargo test -p eggress-cli --test cli_exit_codes` and
`cargo test -p eggress-cli --test cli_tests` (occupied-port bind exit).

## Structured diagnostics

- `DiagnosticCode` enum (`eggress-pproxy-compat/src/diagnostics.rs`) for
  stable error/warning codes; wrap in `StructuredDiagnostic` for JSON output.
- `PproxyCheckOutput` drives `pproxy check --json`.
- Redact credentials in all diagnostics (see `.skills/security-dev/skill.md`).

## Admin HTTP (`eggress-admin`)

Hyper-based local operational server reading the live snapshot per request,
so reloads take effect without restarting admin. Admin stops last in the
shutdown order.

| Endpoint | Method | Role |
|---|---|---|
| `/-/health` | GET | Liveness — always `200 "ok"` when serving |
| `/-/ready` | GET | Readiness gate — `200 "ready"` or `503 "not ready"` |
| `/-/status` | GET | JSON: version, generation, uptime, active connections, listeners |
| `/-/routes` | GET | JSON: compiled rules, default action, rule count |
| `/-/upstreams` | GET | JSON: groups with members, protocols, health, scheduler, in-flight counts |
| `/-/config` | GET | JSON: config summary counts + listener names |
| `/-/udp` | GET | JSON: association/target-flow gauges, per-listener associations |
| `/-/route-explain` | POST | Dry-run routing: `{target, listener, protocol, source?, identity?}` (POST-only; body capped at 16 KiB) |
| `/metrics` | GET | Prometheus text; 404 when metrics disabled |

PAC generation/serving and static content (`--pac`, `--get` compat paths)
are served here. Tests: `cargo test -p eggress-runtime --test admin`.

## Metrics (`eggress-metrics`)

Single Prometheus `MetricsRegistry` owning every metric family. The data
plane records through the server's `SessionMetrics` trait
(`record_auth_failure()` is session-only); runtime/reload/platform metrics
live on `eggress_metrics::RuntimeMetrics`. UDP relay, Shadowsocks, H2, and
transparent-proxy subsystems bridge live atomics with delta-promotion to
avoid double-counting. Keep label cardinality bounded; bridge new metrics
into the registry and cover them in
`crates/eggress-runtime/tests/observability.rs`.

`eggress_auth_failures_total` counts all inbound auth failures (SOCKS5,
HTTP proxy-auth, reverse) for brute-force monitoring.

## System proxy (`eggress-system-proxy`)

Leaf crate reading/mutating OS proxy configuration via structured
`Command { program, args }` execution only. Per-platform capability
classification; credential redaction. Compat `--sys` applies the bound local
listener after bind (prefers local SOCKS5 over HTTP) and restores captured
settings on shutdown or failed startup. Test rollback paths with
`MockCommandRunner`; do not use public-internet fixtures.
